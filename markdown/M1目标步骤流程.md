## 三、已定决策（4 项 + 1 补充，后续不得反复）

| # | 决策点 | 选择 | 关键含义 |
|---|---|---|---|
| 1 | location 获取方式 | B：C++ 端缓存 | 用 `unordered_map<string, int>` 缓存，首次查、之后复用 |
| 2 | 资源所有权 | A：禁拷贝 + 实现移动 | 拷贝构造/赋值 `= delete`；移动构造/赋值自实现 |
| 3 | 文件读取 | A：`ifstream` + `istreambuf_iterator` | 读取失败报错退出，不做 fallback |
| 4 | uniform 传值接口 | 函数重载 | 一个名字（如 `Set`），按值类型重载；当前 vec4 + mat4 |
| 补充 | 构造函数收"源码字符串" | 文件读取发生在 Shader 外部 | Shader 不碰文件 I/O，解耦；读文件写在 Render 或 helper |

## 五、步骤拆解（7 步）

> 每步给出：目标 / 要做什么 / 完成判据 / 依赖。判据尽量落到"代码里能查到的信号"。

### 步骤 1：Shader 类头文件骨架

- **目标**：确定 Shader 类对外职责与内部成员，写好头文件声明。
- **要做什么**：声明类；划清公有/私有；确定成员（程序句柄 + location 缓存表）；声明编译/链接辅助函数为 static。
- **完成判据**：
  - `include/Rendering/Shader.h` 中存在 `class Shader`（`namespace Rendering`）。
  - 私有成员含：程序句柄（`unsigned int`）、location 缓存表（`unordered_map<std::string, int>`）。
  - 私有静态：`CompileShader`、`CreateShaderProgram`。
  - 公有：构造函数（收源码字符串）、析构函数、Set 重载（名字 + 值）。
  - 拷贝构造/赋值 `= delete`；移动构造/赋值声明（`noexcept`）。
- **依赖**：无。
- **当前状态**：**基本完成**。但 Set 仍是无参 `void set_Uniform()`，需补参数与重载（见步骤 5）；include 需按 Q3 修正。

### 步骤 2：文件读取（发生在 Shader 外部）

- **目标**：能从 `shader/default.vert` / `default.frag` 读出字符串，供 Shader 构造使用。
- **要做什么**：写一个"读文件 → 字符串"的能力（决策 3 的 `ifstream` + `istreambuf_iterator`）；读取失败报错退出。
- **完成判据**：
  - 存在"读文件 → 字符串"的代码路径。
  - 调用方能拿到两个着色器的源码字符串去构造 Shader。
  - 位置（Render.cpp 或单独 helper）由开发者决定，但**不得写在 Shader 类内部**（决策补充）。
- **依赖**：无（可与步骤 3 并行）。
- **当前状态**：未开始。

### 步骤 3：编译 + 链接（迁入 Shader.cpp）

- **目标**：把 `Render.cpp` 现有的 `CompileShader` / `CreateShaderProgram` 迁进 `Shader.cpp`。
- **要做什么**：实现两个 static 函数；保留编译/链接失败的报错行为。
- **完成判据**：
  - `Shader.cpp` 中存在 `CompileShader`、`CreateShaderProgram` 实现。
  - `Render.cpp` 中不再存在这两个函数。
- **依赖**：步骤 1。
- **当前状态**：未开始。

### 步骤 4：资源所有权（析构 + 禁拷贝 + 移动）

- **目标**：Shader 正确释放 program，可移动、不可拷贝。
- **要做什么**：
  - 析构函数释放 program（`glDeleteProgram`）。
  - 实现移动构造/赋值：转移程序句柄（源置 0）、移动缓存表、其余成员按需处理。
  - 拷贝构造/赋值保持 `= delete`。
- **完成判据**：
  - `Shader.cpp` 中析构含 `glDeleteProgram`。
  - `Shader.cpp` 中移动构造/赋值实现：转移 `m_ShaderProgram` 并把源置 0。
  - 头文件中拷贝 `= delete`、移动 `noexcept` 声明齐备。
- **依赖**：步骤 1。
- **当前状态**：头文件声明已就位；`.cpp` 实现未开始。

### 步骤 5：激活 + uniform 传值（重载 + location 缓存）

- **目标**：提供 `Set(名字, 值)` 重载；内部查/填 location 缓存，再 `glUniform*`。
- **要做什么**：
  - `Set` 按值类型重载（当前 vec4、mat4）。
  - 内部流程：查缓存表 → 命中则用，未命中则 `glGetUniformLocation` + 存入 → 调对应 `glUniform*`。
  - 提供"激活 program"的能力（供 Render 使用）。
- **完成判据**：
  - `Shader.h` 中 Set 至少两个重载（`vec4`、`mat4`），均收"名字 + 值"。
  - `Shader.cpp` 中 Set 内部出现：查表（`find`）、`glGetUniformLocation`（未命中时）、对应 `glUniform*`。
  - **注意**：`glGetUniformLocation` / `glUniform*` 从此只允许出现在 `Shader.cpp` 内。
- **依赖**：步骤 3、4。
- **当前状态**：未开始（Q1 的 vec3/vec4 取舍会直接影响此处重载设计）。

### 步骤 6：改造 Render 使用 Shader

- **目标**：Render 持有 Shader，不再硬编码 GLSL、不再裸调 uniform。
- **要做什么**：
  - 删除 `Render.cpp` 的硬编码 GLSL 字符串（OnAttach 里的 vertexSource/fragmentSource）。
  - 读文件（步骤 2）→ 构造 Shader → 让 Render 持有它。
  - `OnUpdate` 改用 `shader.Set(...)` 传 uModel / uColor。
  - 处理 Render 如何"持有不可拷贝的 Shader"（unique_ptr 或移动）。
- **完成判据**：
  - `Render.cpp` 中不再出现 `#version 430` / `layout (location` 等硬编码 GLSL。
  - `Render.cpp` 中不再出现 `glGetUniformLocation` / `glUniform*`。
  - `Render.cpp` 中出现 Shader 类型的使用（构造 + Set 调用）。
- **依赖**：步骤 2、3、4、5。
- **当前状态**：未开始。**潜在卡点**：非拷贝 Shader 的持有方式（unique_ptr 或移动语义）。

### 步骤 7：编译 + 回归验证

- **目标**：构建通过，渲染结果与改造前一致。
- **要做什么**：编译；运行；目视对比 3×3 网格的颜色与位置是否与之前完全一致。
- **完成判据**：
  - 构建成功（无编译/链接错误）。
  - 3×3 网格视觉无变化（颜色、位置、大小）。
  - 对照"二、验收标准"逐条勾选。
- **依赖**：步骤 2~6 全部完成。
- **当前状态**：未开始。
